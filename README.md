# BhumiDorpon (ভূমিদর্পণ)

Bangladesh land-change records and multi-hazard map dashboard, with a parcel-level land information search. Built by Team GeoNeural for the LandTech Innovation Hackathon 2026.

> **Demo data notice.** Every landowner name, Dag No., Khatian No., coordinate, loan or mortgage record and compensation figure in this project is synthetic and generated by a script. The app does not connect to any government, bank or land-office system. It is an educational prototype and not a source of legal land records.

## 1. What the project does

BhumiDorpon has two connected parts.

### 1.1 Disaster land-change dashboard

Five modules show how land changes in Bangladesh: River Erosion, Flood, Landslide, Char (river island) formation, and Coastal erosion and accretion. Each module has a recorded view and a forecast view, a before/after map comparison with synchronized pan and zoom, and per-plot ownership and compensation tables. Forecast views deliberately hide paid, approved and pending status.

### 1.2 Land Information search

The `/land-information` page lets a user pick District, Upazila, Mouza, Dag No. and Khatian No. and receives a report with seven primary cards in this order: land identity and area, ownership, sale and transfer, legal information, land development tax, registration and land history, and bank loan or mortgage information. Disaster history and risk forecasts for the parcel appear below those cards. A missing loan record is shown as "unknown", never as "no loan".

The interface is Bangla by default with an English toggle. Maps are Leaflet maps, with an offline vector "Light GIS" basemap and an Esri satellite basemap.

## 2. How to run it (step by step)

### 2.1 Install the prerequisites

| Tool | Version | Check with |
|---|---|---|
| Node.js | 18.17 or newer (20 LTS recommended) | `node -v` |
| npm | 9 or newer (comes with Node.js) | `npm -v` |

Download Node.js from https://nodejs.org if it is not installed. About 1 GB of free memory is needed because the npm scripts cap Node at 1.5 GB.

### 2.2 Get the code

Either clone the repository:

```bash
git clone https://github.com/panthoraj-005/Bhumi-Dorpon.git
cd Bhumi-Dorpon
```

or unzip the downloaded `Bhumi-Dorpon-main.zip` and open a terminal inside the extracted `Bhumi-Dorpon-main` folder (the one that contains `package.json`).

### 2.3 Install dependencies

```bash
npm install
```

This takes under a minute on a normal connection. `npm ci` also works and installs the exact versions in `package-lock.json`.

### 2.4 Start the development server

```bash
npm run dev
```

Wait until the terminal prints `Ready`. The first page compile takes about 10 to 15 seconds.

### 2.5 Open the app

Go to http://localhost:3000 in a browser. If port 3000 is busy, run `npm run dev -- -p 3001` and open http://localhost:3001 instead.

### 2.6 Enter as a demo user

On the first screen click **"Demo / ডেমো হিসেবে প্রবেশ করুন"**. No account, internet-hosted backend or API key is needed.

### 2.7 Optional: build, test, regenerate data, environment variables

#### Production build

```bash
npm run build
npm start
```

#### Run the tests

```bash
npm test
```

Expected result: 16 test files and 102 tests, all passing. For TypeScript checking run `npm run lint`, which runs `tsc --noEmit`. End-to-end tests (`npm run test:e2e`) use Playwright and need browsers installed first with `npx playwright install`.

#### Regenerate the mock data

```bash
npm run generate:mocks
```

This rewrites the JSON files in `mocks/` and `public/mocks/` from `scripts/generate-mocks.ts`. The generator uses a fixed random seed, so it produces the same data every time.

#### Environment variables

None are required. To use a different map tile provider, create a `.env.local` file with either of these:

```
NEXT_PUBLIC_SATELLITE_TILE_URL=<your satellite tile URL template>
NEXT_PUBLIC_STREET_TILE_URL=<your street tile URL template>
```

### 2.8 Troubleshooting

| Problem | Fix |
|---|---|
| `EADDRINUSE` / port already in use | Start on another port: `npm run dev -- -p 3001` |
| Satellite basemap is blank | It streams tiles from Esri and needs internet. Switch to **Light GIS**, which works offline. |
| Out-of-memory error on a small machine | Close other programs. The scripts already set `--max-old-space-size`. |
| Stale behaviour after pulling changes | Delete the `.next` folder and run `npm run dev` again. |
| Old Node.js version errors | Upgrade to Node.js 18.17 or newer. |

### 3.2 Log in and the Home Dashboard

1. Open the app. On the first screen choose one of three options: log in with an existing account, register a new account, or click **Demo / ডেমো হিসেবে প্রবেশ করুন** to enter without an account.
2. After login the **Home Dashboard** opens. This is the overview page.
3. At the top of the dashboard use the **Recorded / Forecast** switch to change between officially recorded figures and deep-learning projections.
4. The dashboard shows total land lost (eroded or inundated), new land gained (accretion), the net balance, the compensation budget, a breakdown of impact by hazard type, the most affected districts, a live-status panel, a small map preview, and cards for the five hazard modules. Clicking a module card opens that module.

### 3.3 Land Information: search for a parcel

Use this page to look up one land parcel.

1. Click **Land Information (ভূমির তথ্য)** in the sidebar.
2. Enter or choose the details in order: **District**, **Upazila**, **Mouza**, **Dag No.** and **Khatian No.** Type the Dag and Khatian numbers exactly as they appear in the record, because leading zeros are kept.
3. Run the search. If the parcel exists in the demo data, a report opens.
4. The report starts with seven cards in this order: land identity and area, ownership, sale and transfer, legal information, land development tax, registration and land history, and bank loan or mortgage information. A field with no data is shown as unknown, not as "none".
5. Below the seven cards is the disaster section. It lists past land loss or gain from river erosion, flood, landslide, char or coastal change, and it shows the estimated chance (in percent) that this parcel will be lost to each hazard in the coming year. This estimate is a demonstration value and not a legal finding.

### 3.4 How the four hazard modules work (common pattern)

River Erosion, Char, Coastal and Landslide all follow the same page design. Sections 3.5 to 3.8 describe each one separately; this section explains the shared steps.

1. Open the module from the sidebar. A landing page explains the module. Click through to the detail page.
2. At the top of the page choose the mode with the toggle: **A. Recorded Data** (a report based on recorded, surveyed data) or **B. Forecast (DL)** (a report produced by the deep-learning model).
3. Use the **selector chain**, a row of dependent drop-downs, to enter the place. Each choice narrows the next one. When the last drop-down is filled, the page loads.
4. **Maps.** Two maps are shown side by side. In Recorded mode the left map is one year earlier and the right map is the present. In Forecast mode the left map is the present and the right map is the predicted future. Panning or zooming one map moves the other. Buttons let you zoom and switch between the Light GIS and Satellite basemaps.
5. **Dashboard.** Below the maps are summary cards for that area, such as total loss, gain, yearly rate and trend. Each module adds its own cards (see the sub-sections).
6. **Table.** At the bottom is a table of landowners. In Recorded mode it shows the owner's name, Dag No., Khatian No., the land lost or gained, the estimated compensation, whether it has been paid (Paid, Approved or Pending), and the amount paid. In Forecast mode it shows the owner's name, Dag No., Khatian No., the projected affected area and a projected compensation estimate; paid status is not shown because nothing has been paid yet. Click a table row to highlight that plot on the map, or click a plot on the map to highlight its row. The table can be sorted and exported.
7. Use **Reset** in the selector chain to return to the default pilot area. If the chosen place has no event, the page says so in plain words instead of showing an empty map.

### 3.5 River Erosion

Use this module to see how a river has eaten into the land along its banks.

1. Click **River Erosion (নদীভাঙন)** in the sidebar, then open the detail page.
2. Choose **A. Recorded Data** or **B. Forecast (DL)** at the top.
3. Choose, in order: **District**, **Upazila**, **River**, **Riverside Mouza**.
4. In Recorded mode, compare the map from one year ago with the present map. In Forecast mode, compare the present map with the predicted map one year ahead.
5. Read the dashboard: period, average yearly rate, total loss, total gain and trend (increasing, decreasing or stable), plus percentage change against the previous survey and the average riverbank displacement.
6. Read the table at the bottom: owner name, Dag and Khatian numbers, area lost and compensation (Recorded), or projected area and projected compensation (Forecast).

### 3.6 Char (river islands)

Use this module to see new sandbar land that is forming in rivers (accretion) and how it compares with land lost at its edges.

1. Click **Char Islands (চর ও দ্বীপাঞ্চল)** in the sidebar, then open the detail page.
2. Choose **A. Recorded Data** or **B. Forecast (DL)**.
3. Choose, in order: **District**, **Upazila**, **River System**, **Char Island**.
4. Compare the maps: one year ago against the present (Recorded), or the present against the predicted shape (Forecast, shown as a one-year change in shape).
5. Read the dashboard: accretion rate, total accretion, flank scour (edge erosion), net growth, and an emergence stability index.
6. Read the table. Char land that is not yet owned is state-owned Khas land, and such rows show compensation as not applicable.

### 3.7 Coastal erosion and accretion

Use this module for shoreline change along the coast: land lost to the sea and new mudflat land that builds up.

1. Click **Coastal Shifts (উপকূলীয় পরিবর্তন)** in the sidebar, then open the detail page.
2. Choose **A. Recorded Data** or **B. Forecast (DL)**.
3. Choose, in order: **District**, **Upazila**, **Coastal Mouza / Strip**. There is no river or hill step here.
4. Compare the maps: one year ago against the present (Recorded), or the present against the predicted shoreline (Forecast).
5. Read the dashboard: the yearly accretion or erosion rate, intertidal (mudflat) gain, marine erosion, net change, and coastal cards such as the mangrove greenbelt, the 340 m protective buffer and the tenure type (for example virtual-mouza Khas land).
6. Read the table of owners and their affected land and compensation.

### 3.8 Landslide

Use this module to study a hill slope that failed and how much hill land moved.

1. Click **Landslide Hazards (ভূমিধস ঝুঁকি)** in the sidebar, then open the detail page.
2. Choose **A. Recorded Data** or **B. Forecast (DL)**.
3. Choose, in order: **District**, **Upazila**, **Hill Feature**, **Landslide Event**. The event list is sorted newest first and the newest event is selected automatically. If a hill has no recorded landslide, the page says so.
4. The two maps show terrain, not just boundaries. The left map shows the slope before the failure and the right map shows it after (or the predicted state in Forecast mode), with elevation tint, hillshade and contour lines drawn from the demo terrain data.
5. Read the dashboard: event period, displacement rate, displaced hill land, slope gradient, volume of debris moved, homesteads inside the risk buffer, and an impact and damage summary for the selected event.
6. Read the table of affected owners and homesteads with their Dag and Khatian numbers, affected area and compensation.

### 3.9 Flood

The Flood module works differently from the other four. It starts from a mouza and its list of past floods, and it ends at individual landowners.

1. Click **Flood Monitoring (বন্যা পর্যবেক্ষণ)** in the sidebar.
2. Choose, in order: **District**, **Upazila**, **Mouza**, and optionally **Flood Event Year**. You can also filter the list by year.
3. The page lists the floods that have happened in that mouza. Each card shows the flooded area, maximum water depth, how many days the water stayed, and the number of affected owners.
4. Click one flood to open it. You see a before-flood map and an after-flood map, and a **Recorded / Forecast** toggle.
5. Below the maps is a dashboard for that flood: event date and year, flooded area, maximum depth, duration, and number of parcels. A depth legend explains the colours (deep above 1.5 m, moderate 0.5 to 1.5 m, shallow below 0.5 m).
6. Below the dashboard is the **list of landowners** in this mouza. Search by owner name, and use **Export CSV** to download the list. Each row shows the owner, Dag No., Khatian No., flooded area and depth class.
7. Click **Owner Land Page** on a row to open that owner's page (see 3.10).

### 3.10 Owner land page, four corners and Google Earth

This page is reached from the Flood module's landowner list.

1. The top of the page shows the owner's profile card: name, father's name, contact, mouza, number of plots, total area and total flooded area.
2. A map shows the owner's plots. Submerged plots, dry plots and other (dimmed) plots use different colours. Click **Reset Zoom** to return to the full view.
3. Below the map is the **plot list**. Each card shows the Dag No., Khatian No., land class, area and flood status. Click a card to zoom the map to that plot.
4. Open **Four Corner Coordinates** on a card to see the latitude and longitude (six decimals) of the NW, NE, SE and SW corners. Click **Copy 4 corners** to copy them, or **Copy all coordinates** to copy every plot. Use **Download CSV** or **Download GeoJSON** for the whole list.
5. Click **Open in Google Earth** on a plot card. The app downloads a small KML file that outlines the plot and opens Google Earth on the plot, so the user can find the boundary on the satellite image. Open the downloaded file in Google Earth if it does not open automatically.

### 3.11 Settings: account, log out, About, Team

1. Click **Settings** at the bottom of the sidebar.
2. **Account & Profile** shows the full name, username, email and role of the logged-in user (a demo visitor appears as Demo Inspector).
3. Click **Log out** at the bottom of the account card to end the session.
4. **About Project** opens the project description and the architecture and data disclosures.
5. **Team Information** opens the team page with the team name and members.

### 3.12 Language, units and basemap

- **Language.** Click **বাংলা | English** in the header at any time. Bangla is the default. Tables, labels and numbers change language without reloading the page.
- **Area unit.** Switch between decimals, acres and hectares from the unit buttons in the header. All area figures update at once.
- **Basemap.** On any map choose **Light GIS** (works offline) or **Satellite** (needs internet) from the basemap switcher.
- **Sharing a view.** The selected place is kept in the page address, so copying the address from the browser bar reopens the same place.


## 4. Data used

All data is synthetic and deterministic. Nothing is fetched from a government source.

### 4.1 Mock datasets

The files are generated by `scripts/generate-mocks.ts` with a fixed seed (`0x20261011`), so every run gives the same output. Real Bangladesh district, upazila and river names are used as labels to make the demo realistic, but the parcel and owner records attached to them are invented.

| Dataset | File(s) | Size |
|---|---|---|
| Districts | `districts.json` | 12 |
| Upazilas | `upazilas.json` | 36 |
| Mouzas | `mouzas.json` | 108 |
| Landowners | `owners.json` | 40 |
| Cadastral plots (Dag, Khatian, four-corner polygon) | `plots.json` | 3,527 |
| Rivers | `rivers.json` | 12 |
| Hills | `hills.json` | 12 |
| Char islands | `chars.json` | 21 |
| Hazard event data | `river_erosion.json`, `flood.json`, `landslide.json`, `char.json`, `coastal.json` | one file per hazard |
| Per-area map packages (GeoJSON) | `areas/<hazard>/*.json` | 30 areas: 7 river erosion, 6 flood, 6 landslide, 5 char, 6 coastal |
| Landslide terrain rasters | `rasters/<area>/` elevation, slope and hillshade PNGs, contours, spot heights | 6 landslide areas |
| Hillshade images | `hillshades/` | 36 PNG files |
| Dashboard summary | `summary.json` | 1 file |

### 4.2 Where the files live

- `public/mocks/` is served to the browser and loaded through `lib/data.ts`.
- `mocks/` is a mirrored copy that Node.js and the Vitest tests read from disk.
- Land Information reports, including the loan and mortgage card, are built deterministically in `lib/landSearch.ts` from the plot and owner data above.

### 4.3 External services

| Service | Use | Needed to run? |
|---|---|---|
| Esri World Imagery tiles | Satellite basemap | Only for that basemap. Needs internet. |
| OpenStreetMap tiles | Optional street basemap | Only for that basemap. Needs internet. |
| Light GIS basemap | Built-in vector basemap drawn with SVG | No. Works offline. |

### 4.4 Libraries used

Next.js 14, React 18, TypeScript, Tailwind CSS, Leaflet and react-leaflet, Turf.js (polygon and four-corner geometry), Zustand (state), TanStack React Query (data loading), Recharts (charts), Radix UI and Lucide icons, Vitest and Playwright (testing).

### 4.5 Guardrails

- Forecast views never show paid, approved or pending status or any disbursed amount (hackathon Rule 5). They show only projected area and a projected compensation estimate.
- Deep-learning risk figures in the parcel report are demonstration outputs from the synthetic generator, not predictions from a trained model, and are never a legal determination.
- Loan and mortgage records are sample data labelled "Demo data". Unknown stays unknown, and loan references are masked.

## 8. Known limitations

- It is a client-side prototype with no backend, no real login, and no live government or bank data.
- Sessions and users are stored in browser `localStorage` for demonstration only.
- Only the pilot districts, upazilas and areas listed in section 4 are covered.
- Satellite tiles need internet access.
- `next.config.js` currently sets `ignoreBuildErrors` and `ignoreDuringBuilds`, so `npm run build` does not fail on type or lint errors. Run `npm run lint` separately to check types.
