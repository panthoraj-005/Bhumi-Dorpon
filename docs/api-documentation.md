## 1. API Overview

> [!IMPORTANT]
> **NO INTERNAL REST OR GRAPHQL SERVER ENDPOINTS EXIST.**
> Inspection of the BhumiDorpon codebase confirms that **no internal backend API routes (`/api/...`) or Next.js server actions are currently implemented**. 
> The application functions as a client-side architecture where UI components query an asynchronous TypeScript data access module ([`lib/data.ts`](file:///d:/SOFTWARE/Project/Antigravity/BhumiDorpon/lib/data.ts)) that reads from local bundled JSON files.

The network traffic generated by BhumiDorpon is strictly confined to:
1. Standard browser asset loading (HTML, CSS, JavaScript bundles, local JSON mocks, and SVG icons).
2. Outbound `HTTPS GET` tile requests to third-party public raster basemap tile providers (Esri World Imagery and OpenStreetMap).

## 2. Verified In-Memory Client Data Interfaces (`lib/data.ts`)

Although no HTTP REST endpoints exist on the wire, [`lib/data.ts`](file:///d:/SOFTWARE/Project/Antigravity/BhumiDorpon/lib/data.ts) exposes a typed asynchronous API that mirrors the signature of a production RESTful microservice.

### 2.1 `getDashboardSummary(mode)`
- **Purpose:** Fetches nationwide aggregated land loss, gain, affected owner count, and compensation liability.
- **Parameters:**
  - `mode: "recorded" | "forecast"`
- **Response Format:**
  ```typescript
  export interface DashboardSummary {
    mode: "recorded" | "forecast";
    totalLossDecimal: number;
    totalGainDecimal: number;
    totalNetChangeDecimal: number;
    affectedOwnersCount: number;
    compensation: {
      estimatedBDT: number;
      paidBDT?: number;      // STRICTLY OMITTED in forecast mode
      approvedBDT?: number;  // STRICTLY OMITTED in forecast mode
      pendingBDT?: number;   // STRICTLY OMITTED in forecast mode
    };
    trends: { year: number; lossDecimal: number; gainDecimal: number }[];
    hazardBreakdown: { hazard: HazardType; lossDecimal: number; gainDecimal: number }[];
    topDistricts: { districtId: string; districtName: string; lossDecimal: number }[];
  }
  ```

### 2.2 `getOptions(hazard, mode, step, selectionSoFar)`
- **Purpose:** Resolves dependent cascading selector choices.
- **Parameters:**
  - `hazard: HazardType` (`"river_erosion"` | `"flood"` | `"landslide"` | `"char"` | `"coastal"`)
  - `mode: "recorded" | "forecast"`
  - `step: number` ($1$ = District, $2$ = Upazila, $3$ = River/Hill/Mouza, $4$ = Result)
  - `selectionSoFar: Partial<SelectorState>`
- **Response Format:**
  ```typescript
  export interface SelectorOption {
    value: string;
    label: string;
    hasRecords?: boolean; // Indicates if demo data exists for this node
    subtext?: string;
  }
  ```

### 2.3 `getFlood(floodId)`
- **Purpose:** Retrieves a detailed flood event record, including multi-depth inundation geometries and cadastral plot statuses.
- **Parameters:**
  - `floodId: string` (e.g., `"flood_sylhet_2024"`)
- **Response Example:**
  ```json
  {
    "id": "flood_sylhet_2024",
    "mouzaId": "m_jaflong_01",
    "year": 2024,
    "severity": "Severe",
    "floodedAreaDecimal": 1240.5,
    "maxDepthM": 2.1,
    "durationDays": 14,
    "affectedOwnersCount": 42,
    "geometry": {
      "shallowZone": [[[91.98, 25.12], [92.02, 25.12], [92.02, 25.16], [91.98, 25.16]]],
      "moderateZone": [[[91.99, 25.13], [92.01, 25.13], [92.01, 25.15], [91.99, 25.15]]],
      "deepZone": [[[91.995, 25.135], [92.005, 25.135], [92.005, 25.145], [91.995, 25.145]]]
    }
  }
  ```

### 2.4 `getOwnerPlots(floodId, ownerId)`
- **Purpose:** Fetches all cadastral land parcels owned by a specific citizen within a flood event, detailing **four-corner boundary coordinates**.
- **Parameters:**
  - `floodId: string`
  - `ownerId: string` (e.g., `"own_karim_104"`)

## 3. Verified External Services and Network Integrations

The application communicates over HTTPS with external raster tile endpoints configured in [`lib/basemapConfig.ts`](file:///d:/SOFTWARE/Project/Antigravity/BhumiDorpon/lib/basemapConfig.ts):

### 3.1 Esri World Imagery (Satellite Basemap)
- **Host / URL Template:**  
  `https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}`
- **HTTP Method:** `GET`
- **Parameters:**
  - `{z}`: Zoom level ($1 - 19$)
  - `{y}`: Tile row coordinate
  - `{x}`: Tile column coordinate
- **Headers:** Standard browser HTTP headers; no authentication tokens required.
- **Payload / Response:** 256x256 pixel JPEG satellite imagery tiles.
- **Attribution Obligation:** Must display visible attribution string:  
  `Tiles © Esri — Source: Esri, i-cubed, USDA, USGS, AEX, GeoEye, Getmapping, Aerogrid, IGN, IGP, UPR-EGP, and the GIS User Community`.

### 3.2 OpenStreetMap Cartographic Tiles (Street Basemap Fallback)
- **Host / URL Template:**  
  `https://tile.openstreetmap.org/{z}/{x}/{y}.png`
- **HTTP Method:** `GET`
- **Payload / Response:** 256x256 pixel PNG standard cartographic street tiles.
- **Attribution Obligation:** `© OpenStreetMap contributors`.
- **Usage Policy:** Strictly complies with OSM Foundation Tile Usage Policy (standard User-Agent header, no mass scraping).

---

## 4. Error Handling & Fallbacks

- **Simulated Latency:** Calls to `lib/data.ts` resolve via `setTimeout` (200–400ms); errors are returned as rejected Promises.
- **Client Fallback:** If an external tile server is unreachable, Leaflet fires a `tileerror` event. The application catches this event, displays a non-blocking toast alert, and keeps the local synthetic `Light GIS` basemap active.

---

## 5. Authentication and Authorization Requirements

- **Current Prototype:** **None.** All views, data queries, and map comparisons are public and require no authentication or API keys.

---

## 6. Environment Configuration

The application operates without required environment variables. Optional public overrides can be configured in `.env.local`:
- `NEXT_PUBLIC_SATELLITE_TILE_URL`: Custom satellite tile service endpoint.
- `NEXT_PUBLIC_STREET_TILE_URL`: Custom street tile service endpoint.

---

## 7. Known API Limitations

1. **No Data Mutations:** The API is strictly read-only; there are no `POST`, `PUT`, or `DELETE` endpoints to create or update cadastral records.
2. **Client-Side Filtering:** All filtering happens in browser memory; transferring large JSON datasets is unsuited for mobile networks with low bandwidth.

## 9. Addendum — Google Earth Parcel Outline & Five-Hazard Information Store

### 9.1 Client-Side Google Earth Integration (`lib/googleEarth.ts`)
The application exposes a pure TypeScript geospatial helper library (`lib/googleEarth.ts`) for browser-based KML synthesis and Google Earth camera positioning:

| Function | Signature | Description |
|---|---|---|
| `buildParcelKml` | `(parcel: EarthParcel, meta?: EarthOwnerMeta) => string` | Generates valid KML 2.2 XML containing a closed 5-point polygon (clampToGround, orange outline, translucent fill), four corner point placemarks (`1 (NW)` … `4 (SW)`), and complete owner/cadastral metadata with mock-data disclaimer. Throws error if `parcel.corners` length is not exactly 4. |
| `parcelRingToKmlCoordinates` | `(corners: EarthCorner[]) => string` | Serializes 4 corners into 5 space-separated `lon,lat,0` tuples with first point repeated last. |
| `getParcelCenter` | `(corners: EarthCorner[]) => { lat: number; lon: number }` | Computes bounding-box center `(min + max) / 2`. |
| `getCameraRangeMeters` | `(corners: EarthCorner[]) => number` | Computes larger parcel extent in meters (minimum 20m) and scales by 3 for optimal Google Earth camera framing. |
| `buildEarthCameraUrl` | `(corners: EarthCorner[]) => string` | Produces Google Earth web URL: `https://earth.google.com/web/@<lat>,<lon>,0a,<range>d,35y,0h,0t,0r`. |
| `buildKmlFileName` | `(parcel: { dagNo: string }, meta?: { floodId?: string }) => string` | Returns sanitized lowercase filename: `<floodId>_dag_<dagNo>_outline.kml`. |
| `escapeXml` | `(str: string) => string` | Escapes `&`, `<`, `>`, `"`, `'` characters for safe XML embedding. |
| `openParcelInGoogleEarth` | `(parcel: EarthParcel, meta?: EarthOwnerMeta) => { fileName, earthUrl }` | Browser-only: triggers synchronous `window.open(earthUrl, "_blank")` followed by `Blob` + temporary `<a download>` trigger and revocation. |

### 9.2 Five-Hazard Information Store Endpoints & Layer
Data is served as static, deterministic JSON files without database overhead:
- **Client Endpoints:** Served via `/mocks/*.json` from `public/mocks/` (`river_erosion.json`, `flood.json`, `landslide.json`, `char.json`, `coastal.json`, and shared indices).
- **Per-Area Map Packages:** `/mocks/areas/<hazard>/area_*.json` resolved dynamically by `getMapArea()` using `areas_index.json`.
- **Single Access Layer:** UI components consume datasets strictly through cached async getters in `lib/data.ts`.
