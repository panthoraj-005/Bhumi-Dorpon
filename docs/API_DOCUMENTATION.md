## 1. API Architecture Overview

> [!IMPORTANT]
> **NO INTERNAL REST OR GRAPHQL SERVER ENDPOINTS EXIST IN THE CURRENT CODEBASE.**
> Inspection of the BhumiDorpon repository confirms that **no backend HTTP routes (`/api/...`) or Next.js server actions are currently implemented**. 
> The application functions as a client-side architecture where UI components query an asynchronous TypeScript data access module ([`lib/data.ts`](file:///d:/Project/Antigravity/BhumiDorpon/lib/data.ts)) that reads static demonstration JSON files.

The network traffic generated by BhumiDorpon is strictly confined to:
1. Standard browser asset loading (HTML, CSS, JavaScript bundles, local JSON mocks, and SVG icons).
2. Outbound `HTTPS GET` tile requests to third-party public raster basemap tile providers (Esri World Imagery and OpenStreetMap).
3. Outbound navigation to Google Earth Web (`https://earth.google.com/web/@...`) when initiated by user action.

## 2. Verified In-Memory Client Data Interfaces (`lib/data.ts`)

Although no HTTP REST endpoints exist on the wire, [`lib/data.ts`](file:///d:/Project/Antigravity/BhumiDorpon/lib/data.ts) exposes a typed asynchronous API that mirrors the signature of a production RESTful microservice.

### 2.1 `getDashboardSummary(mode)`
- **Purpose:** Fetches nationwide aggregated land loss, gain, affected owner count, and compensation liabilities.
- **Parameters:**
  - `mode: "recorded" | "forecast"`
- **Response Format:**
  ```typescript
  export interface DashboardSummary {
    mode: "recorded" | "forecast";
    totalLossDecimal: number;
    totalGainDecimal: number;
    totalNetChangeDecimal: number;
    affectedOwnersCount: number;
    compensation: {
      estimatedBDT: number;
      paidBDT?: number;      // STRICTLY OMITTED in forecast mode (Rule 5)
      approvedBDT?: number;  // STRICTLY OMITTED in forecast mode (Rule 5)
      pendingBDT?: number;   // STRICTLY OMITTED in forecast mode (Rule 5)
    };
    trends: { year: number; lossDecimal: number; gainDecimal: number }[];
    hazardBreakdown: { hazard: HazardType; lossDecimal: number; gainDecimal: number }[];
    topDistricts: { districtId: string; districtName: string; lossDecimal: number }[];
  }
  ```

### 2.2 `getOptions(hazard, mode, step, selectionSoFar)`
- **Purpose:** Resolves dependent cascading selector choices based on active parent selections.
- **Parameters:**
  - `hazard: HazardType` (`"river_erosion"` | `"flood"` | `"landslide"` | `"char"` | `"coastal"`)
  - `mode: "recorded" | "forecast"`
  - `step: "district" | "upazila" | "river" | "hill" | "mouza"`
  - `selectionSoFar: Record<string, string>`
- **Response Format:**
  ```typescript
  export interface SelectorOption {
    id: string;
    label: string;
    hasRecords: boolean; // Indicates whether demo data is available
  }
  ```

### 2.3 `listResults(hazard, mode, selection)`
- **Purpose:** Returns list of affected areas matching the cascading selector query.
- **Parameters:**
  - `hazard: HazardType`
  - `mode: "recorded" | "forecast"`
  - `selection: Record<string, string>`
- **Response Format:** Array of typed hazard summaries (`HazardResultItem[]`).

### 2.4 `getResult(hazard, id)`
- **Purpose:** Fetches full spatial detail and landowner registry for a specific hazard result.
- **Parameters:**
  - `hazard: HazardType`
  - `id: string` (e.g., `"res-khanshama-2024"`)

### 2.5 `listFloods(mouzaId)`
- **Purpose:** Lists archived seasonal and flash flood events for a specific mouza.
- **Parameters:**
  - `mouzaId: string` (e.g., `"mouza-jaflong"`)
- **Response Format:** Array of `FloodEventSummary` items including event year, depth classification, and affected plot count.

### 2.6 `getFlood(mouzaId, floodId)`
- **Purpose:** Retrieves complete flood inundation event data including multi-depth contour layers and plot submersion registries.
- **Parameters:**
  - `mouzaId: string`
  - `floodId: string` (e.g., `"flood-jaflong-2024"`)

### 2.7 `getFloodOwners(floodId, query)`
- **Purpose:** Performs client-side filtering across affected landowners by name or Dag No.
- **Parameters:**
  - `floodId: string`
  - `query?: string`
- **Response Format:** Array of `FloodOwnerListItem` records.

### 2.8 `getOwnerProfile(ownerId)`
- **Purpose:** Retrieves owner metadata for the owner detail header.
- **Parameters:**
  - `ownerId: string`
- **Response Format:**
  ```typescript
  export interface OwnerProfile {
    ownerId: string;
    name: string;
    fatherName: string;
    village: string;
    totalOwnedDecimal: number;
  }
  ```

### 2.9 `getOwnerPlots(floodId, ownerId)`
- **Purpose:** Retrieves all cadastral plots owned by an individual within a specific flood event, including verified 4-corner coordinates.
- **Parameters:**
  - `floodId: string`
  - `ownerId: string`
- **Response Format:**
  ```typescript
  export interface OwnerPlotDetail {
    plotId: string;
    dagNo: string;
    khatianNo: string;
    landClass: string;
    areaDecimal: number;
    submersionStatus: "Submerged" | "Partially Submerged" | "Intact";
    depthClass: "Shallow" | "Moderate" | "Deep";
    corners: [
      { cornerIndex: 1; name: "NW"; lat: number; lng: number },
      { cornerIndex: 2; name: "NE"; lat: number; lng: number },
      { cornerIndex: 3; name: "SE"; lat: number; lng: number },
      { cornerIndex: 4; name: "SW"; lat: number; lng: number }
    ];
  }
  ```

### 2.10 `getMapArea(hazard, areaId, mode)`
- **Purpose:** Resolves self-contained map packages containing vector bounds, basemap geometries, and overlay layers.
- **Parameters:**
  - `hazard: HazardType`
  - `areaId: string`
  - `mode: "recorded" | "forecast"`
- **Response Format:** `MapAreaPackage` object loaded via `areas_index.json`.

## 3. Client-Side Export & 3D Earth Interface (`lib/googleEarth.ts`)

BhumiDorpon provides pure client-side spatial serialization in [`lib/googleEarth.ts`](file:///d:/Project/Antigravity/BhumiDorpon/lib/googleEarth.ts):

### 3.1 `openParcelInGoogleEarth(plot)`
- **Purpose:** Orchestrates the simultaneous Google Earth Web tab launch, KML file synthesis, and browser download.
- **Parameters:**
  - `plot: OwnerPlotDetail`
- **Execution:** Synchronous click-handler execution to satisfy browser pop-up blocker constraints.

### 3.2 `buildParcelKml(plot)`
- **Purpose:** Serializes a single parcel's 4-corner boundary into an OGC-compliant KML 2.2 XML string.
- **Parameters:**
  - `plot: OwnerPlotDetail`
- **Output:** Valid KML XML string containing closed polygon, corner placemarks, and demo disclaimers.

### 3.3 `buildEarthCameraUrl(corners)`
- **Purpose:** Computes the Google Earth Web camera URL centered on the parcel bounding box.
- **Parameters:**
  - `corners: CornerCoordinate[]`
- **Output:** `https://earth.google.com/web/@<lat>,<lon>,0a,<range>d,35y,0h,0t,0r`

### 3.4 `buildKmlFileName(floodId, dagNo)`
- **Purpose:** Generates sanitized local filename for the downloaded KML.
- **Output:** `<floodId>_dag_<dagNo>_outline.kml`

## 4. External Network Tile Integrations

### 4.1 Esri World Imagery (Satellite Tiles)
- **Endpoint:** `https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}`
- **Protocol:** Public HTTPS GET
- **Format:** 256x256 JPEG raster imagery tiles
- **Attribution:** `Tiles © Esri — Source: Esri, i-cubed, USDA, USGS, AEX, GeoEye, Getmapping, Aerogrid, IGN, IGP, UPR-EGP, and the GIS User Community`

### 4.2 OpenStreetMap (Standard Street Tiles)
- **Endpoint:** `https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png`
- **Protocol:** Public HTTPS GET
- **Format:** 256x256 PNG raster tiles
- **Attribution:** `© OpenStreetMap contributors`

## 5. Proposed Future Server REST API Specification

When migrating from the demonstration prototype to the production FastAPI / PostGIS backend, the following endpoints will be introduced:

### 5.1 Administrative Endpoints
- `GET /api/v1/districts`: Returns all administrative districts with bounding boxes.
- `GET /api/v1/districts/{id}/upazilas`: Returns upazilas within a district.
- `GET /api/v1/upazilas/{id}/mouzas`: Returns mouzas with JL numbers.

### 5.2 Hazard Analysis Endpoints
- `GET /api/v1/hazards/{hazard}/summary?mode={recorded|predicted}`: National KPI aggregations.
- `GET /api/v1/hazards/{hazard}/events?mouza_id={id}&mode={recorded|predicted}`: Hazard event list for a mouza.
- `GET /api/v1/hazards/{hazard}/events/{id}`: Detailed event metrics and transect retreat rates.

### 5.3 Flood & Cadastral Endpoints
- `GET /api/v1/floods?mouza_id={id}`: Archived flood events.
- `GET /api/v1/floods/{id}`: Inundation contours and affected plot counts.
- `GET /api/v1/floods/{id}/owners?q={search}`: Paginated affected landowner list.
- `GET /api/v1/owners/{id}/plots?flood_id={id}`: Cadastral plot details with 4-corner GPS coordinates.

### 5.4 Spatial GeoJSON & KML Endpoints
- `GET /api/v1/geojson/plots/{id}`: RFC 7946 GeoJSON Feature for a cadastral parcel.
- `GET /api/v1/kml/plots/{id}`: Server-side KML 2.2 export endpoint.

### 5.5 Error Handling Standards (RFC 7807)
All production endpoints will return standard RFC 7807 Problem Details:

```json
{
  "type": "https://api.bhumidorpon.gov.bd/errors/not-found",
  "title": "Hazard Event Not Found",
  "status": 404,
  "detail": "No flood event found matching ID 'flood-jaflong-2099'",
  "instance": "/api/v1/floods/flood-jaflong-2099"
}
```
